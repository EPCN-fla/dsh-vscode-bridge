## Verdict

**对本插件的消费面，整个区间只有 1 项破坏性命中：`@deepseek-ai/dsh-agent-presets` 被拆分移除（DSH-0.1.7-J1-03/J1-16），且 `AgentPreset.trust`/`path` 字段从类型中删除。** 其余 8 个被消费包 + cordis 的插件用得到的符号全部未变或纯增量。2211 个提交中的其余变化（PTC 运行时、Web Client 槽位、图标、设置传输等）与本插件（普通 Host 侧 Cordis 插件，无 Web 面）不相交。会话日志 V3→V4 迁移发生在 `dsh-session-persistence`/`dsh-session-log-export` 内部，本插件只经由其稳定 API 读取，不透出。

## §1 破坏性命中

### HIT-01 · `dsh-agent-presets` 拆分移除（DSH-0.1.7-J1-03 / J1-16）

| 维度 | 0.1.5-rc.2 | 0.1.7-rc.1 |
|---|---|---|
| 包 | `@deepseek-ai/dsh-agent-presets` | 移除；拆为 `dsh-agent-preset` + `dsh-agent-preset-registry` |
| 服务类 | `AgentPresets` | `AgentPresetRegistry` |
| 服务键 | `agentPresets` | `agentPresets`（**未变**）|
| `list()` | `Promise<AgentPreset[]>` | `Promise<AgentPreset[]>`（签名未变）|
| `defaultId` | `string` getter | `string` getter（未变）|
| `composedPreset(ctx)` | `(Context) => string \| undefined` | 同（未变，`agent-preset-registry/src/index.ts:297`）|
| `select(agent, id)` | `(Agent, string) => Promise<string>` | 同（未变，`:326`）|
| `AgentPreset` 字段 | `id, trust: 'system'\|'user', path, name?, description?, order?, broken?` | `id, name?, description?, order?, broken?` — **`trust`/`path` 删除** |

- **谁断**: 本插件 `src/core.ts:17` 类型导入 `AgentPresets`；`src/index.ts:40` 的声明合并副作用导入；`listPresets()` 无条件映射 `preset.trust`（`src/core.ts:499`）。
- **运行时注**: 0.1.3 插件在 0.1.7-rc.1 主机上其实仍可运行（JS 不管类型，四个方法签名一致），但 `trust` 会以 `undefined` 被 JSON 序列化丢弃——即线上已存在该字段缺失的事实。
- **Adapt**: 在 `core.ts` 定义窄结构化切片 `AgentPresetsSlice`（`list`/`defaultId`/`composedPreset`/`select` + `trust?` 可选的花名册条目），删除对两个 preset 包的一切导入；`preset.list` 线协议 `trust` 改为可选（有则透传）。双侧编译均通过，因为切片中的 `Agent`/`Context` 引用跟随当前安装的 cohort。

## 迁移清单

1. `core.ts`：结构化切片 `AgentPresetsSlice`/`AgentPresetListEntry` 取代 `AgentPresets` 类型导入；`trust` 条件映射
2. `index.ts`：删除 `dsh-agent-presets` 副作用导入（`ctx.get('agentPresets')` 走 cordis 未声明键 `any` 重载，与 `sessionQuery` 探针同款）
3. `package.json`：devDeps 9 包 → 0.1.7-rc.1，删除 `dsh-agent-presets`；peer 不动
4. 测试：`core.test.ts` 增补 trust 透传断言 + 无 trust 花名册用例；`compose.test.ts` 增补 preset/permission/session 通道
5. 文档：`preset.list` 线协议 `trust` → `trust?`（0.1.7 主机缺失）；兼容性说明。协议版本保持 1（字段缺失在 0.1.3+0.1.7 主机组合上早已发生，文档化而非新破坏）
6. 双版本矩阵：0.1.7-rc.1 cohort 与 0.1.5-rc.2 cohort 各跑 typecheck+全量单测
7. 独立 `chore(release)` 提交 bump 0.2.0（`package.json` + `PLUGIN_VERSION`）
