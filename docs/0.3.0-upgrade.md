## Verdict

**对本插件的消费面，整个区间零破坏性命中；插件源码无需任何适配性改动即可同时适配 0.1.7-rc.1 与 0.2.0-rc.2。** 8 个被消费包中 6 个 src 零 diff，其余 2 个（`dsh-permission-presets`、`dsh-agent-preset-registry`）的变化均不落在插件消费的符号上。唯二需要随走廊移动而做的**非适配性**清理：① `preset.list` 的 `trust` 透传在 0.1.5 移出走廊后成为死字段；② 文档与注释中的 0.1.5 接线行/版本叙述需要重锚定。新增的运行时兼容预审（§1-N1）强化了 0.1.7-J1-01 的 peer 强制，但结论不变：本插件未声明 DSH peer，双侧均直接通过。

**走廊等价性**: 被消费包的 src 变化全部集中在第一腿（0.1.7-rc.1→0.2.0-rc.1）；第二腿（0.2.0-rc.1→0.2.0-rc.2）对这些目录零 diff。因此 0.2.0-rc.1 与 0.2.0-rc.2 对本插件的消费面完全等价，两端验证即覆盖中点。

## §1 值得记录的变化（均不构成本插件的破坏）

### N1 · 新增运行时兼容预审 `compatibility-preflight`（0.1.7-J1-01 的强化）

| 维度 | 0.1.7-rc.1 | 0.2.0-rc.2 |
|---|---|---|
| 强制点 | 安装期（plugin-manager）+ 启动期 bundle 级跳过 | 追加 **profile 组合期行级预审**：`prepareProfileEntries`/`prepareProfilePatches` 对不满足的 `@deepseek-ai/dsh*` peer 的行置 `disabled`（stderr 报告），Include 触及被拒插件则整体被拒 |
| 豁免机制 | profile `compatibility.json`（已存在） | 同左；CLI 面新增 `dsh plugin allow-version / revoke-version / version-exemptions`（`apps/cli/src/plugin.ts`） |
| 无 peer 声明的插件 | 通过 | **通过**（`evaluatePluginCompatibility` 对无 `peerDependencies` 或仅有非 `@deepseek-ai/dsh*` peer 的 manifest 返回 `undefined`，`plugin-compatibility.ts:48,53`） |

- **谁断**: 声明了 `@deepseek-ai/dsh*` peer 且区间不含当前宿主的插件。**本插件不命中**：`peerDependencies` 只有 `@deepseek-ai/cordis`（`^4.0.2`；cordis 双 tag 均为 4.0.4，见 `vendor/cordis/package.json`），预审循环跳过非 dsh peer。
- **注意**: 预审对行内 manifest 做语义化校验，peer 元数据不可读/非法时该行被拒（"its declared peer dependencies cannot be validated"）——本插件 manifest 字段常规，不受影响。

### N2 · `agent-preset-registry` 移除 `modeSelectionEnabled`

- `Config` zod schema 删除 `modeSelectionEnabled` 键；`AgentPresetRoster` 删除同名字段（`preset.ts`、`types.ts`）。
- **不命中**: 插件消费的 `list()`/`defaultId`/`composedPreset(ctx)`/`select(agent, id)` 四方法签名双 tag 逐字一致（`:290`/`:319`）；插件不读 `AgentPresetRoster`（那是 Web 远程面）。
- **profile 作者注**: 旧 profile 的注册行若带 `config.modeSelectionEnabled`，zod 默认剥离未知键，不报错，静默失效。

### N3 · `permission-presets` 的 Auto 预设语义调整

- `AUTO_PRESET_SPEC.approval` `'never'` → `'ask'`（reviewer 拒绝回路由用户）；`current()` 增加「已选 Auto + approval 为 never 仍归 Auto」的并列判定（委派子代理钉住 never 的场景）。
- **不命中**: 插件只透传 `optionOf(name)`（返回 `{ value, name, description? }`，双 tag 逐字一致）与 `current(session)` 的字符串结果；Auto 规格值不进线上协议。

### N4 · `workspace.initializeDefault` 签名变化

- `resolveDirectory: () => Promise<{ path, title }>` → `() => Promise<string>`（标题改取请求路径的末段）。
- **不命中**: 插件消费 `resolveByPath/create/list/archivedSessionIds/archiveSession` 与 `Workspace.id/path/title/sessionIds/attachSession`、`WorkspaceUnknownSessionError`/`WorkspaceActiveSessionError`（按 `error.name` 判定）——全部双 tag 一致，`:375` 活动会话仍抛 `WorkspaceActiveSessionError`。

### N5 · `dsh-session` 纯增量

- 新增 `Session.toolHistory()`、`ToolCallProjection`、`ToolCallRecovery` 导出；`request/header` 的 `startsSeries` 语义注释改写（字段本身未动）。
- 插件消费的 `Session.id/header`、`SessionHeader`（`cwd/createdAt/parentSession/agentPreset`）、`SessionEvent`、`SessionStore.list/get`、`session/created`/`session/event` 事件——`types.ts` 对应行零 diff。

### N6 · `session-query` 观测读错误包装

- `SessionObservationReader.read` 新增投影失败的 `SessionQueryError(SESSION_QUERY_CORRUPT_SESSION)` 包装（签名未变）。插件只把该服务引用透传给归档模块，不直接调用。

### N7 · `app-boot` profile 装载内部重构

- `Profile` 新增结构化 `skippedBundles`（替代原 stderr 直报）；`generateConfigSchema` 删 `binName` 参数；`reportSkippedBundles` 新导出。均为 CLI/boot 内部面。
- **关键不变量**: `profileContext` 服务键与 `installAnchor` 字段保持（`profile-context.ts:21`；CLI `profile-boot.ts:298` 仍 `hostCtx.provide('profileContext', ...)`）——宿主版本探测主源不受影响。

### N8 · bundle 装配面（README 接线文档的事实源）

- `web-app/presets/standard.patch.yml`（预设声明行形状参考）**双 tag 完全一致**；`acp-app/cordis.patch.yml` **完全一致**。
- `base/cordis.patch.yml` 增量：新增 `otel` 行、`llm-deepseek` 拆为 `…-api-key` + `…-account`、`session-telemetry-otel` 端点与限流字段调整、`dsh-attachment-local`/`dsh-session-query-sqlite` 行原位保留——profile 以 bundle 名引用，自动继承，接线文档无需逐行跟进。
- **结论**: 0.1.7 的接线行集（`agent-preset-registry` 注册行 + `agent-preset` 声明行 + `workspace` + `subagent-model-selection-settings`）在 0.2.0 主机上原样有效。

### N9 · 区间内 revert 复核

7 个 revert 提交（desktop 安装器测试、plugin-manager 行开关 UX ×2、timed question 对账、subagent `list_agents` 描述、desktop 启动器、jsonl 迁移验证器进程隔离）均不触及被消费包——无「先加后撤」陷阱；叠加 §Verdict 的腿级零 diff，中点 rc.1 无隐匿面。
