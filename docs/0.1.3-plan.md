# dsh-vscode-bridge v0.1.3 开发计划：DSH 原生指令与技能通道

> 执行会话请按 §8 清单推进；每节均标注 dsh 侧依据与验收方式。
> 目标版本：`dsh-vscode-bridge@0.1.3`。要求 dsh ≥ 0.1.5-rc.2（与 0.1.2 相同）。

## 0. 背景与调研结论（已核实，勿重复调研）

| 能力 | dsh 侧落点 | acp(-vscode) profile 可用性 |
|---|---|---|
| 指令注册表 | `ctx.commands`（`@deepseek-ai/dsh-commands` 的 `CommandRuntime`）：`@Remote list(agent): readonly CommandDescriptor[]`（`{ definitionId?, name, description, input? }`，按名排序）；`@Remote execute(agent, line, submittedAttachments, signal): Promise<CommandExecution \| undefined>`，`CommandExecution = { commandId, result: { kind: 'success'\|'error', text?, sourceEventSeq? } }`。执行路径与 TUI/Web 完全一致，自动写 `command/run`、`command/done` 生命周期日志 | ✅ 在 dsh-base 的 cordis.patch.yml（`- id: commands`）；`/compact`（command-compact）、`/plan`（plan-mode 经 `ctx.inject(['commands'])` 注册）均在其中 |
| 技能注册表 | `ctx.skills`（dsh-skill）：`list(options?: SkillViewOptions): Promise<SkillSummary[]>`；`SkillSummary = { path?, name, description, whenToUse?, invocation, source, provider, resourceBase? }` | ✅ 在 dsh-base（dsh-skill、skill-filesystem、skill-badge、tool-skill 四行） |
| 计划模式 | `ctx.planMode`（PlanModeController）：`set(agent, active)` → `'committed' \| 'queued' \| 'cancelled' \| 'noop'`；状态事件走 `plan/mode` 投影 | ✅ 经 `/plan` 指令即可触达，bridge 无需直接依赖 |
| 会话导出 | registry 的 `export` 指令（session-log-download）`inject = ['commands', 'connection']`，经 connection 载体流给 Web/Desktop | ❌ ACP 组合无 `connection` 服务，该指令不激活 → 必须绕过指令层，直接复用 `@deepseek-ai/dsh-session-log-export` 的 `archive.ts`：`sessionLogExportDeps(ctx)`（收集 `{ sessionQuery, sessionPersistence, attachments, sessions }`）、`flushLiveSessionLog(deps, id, signal)`、`streamSessionLogZip(...)`、`sessionLogZipFilename(sessionId)` |

核心判断：**不要发明新机制**——`ctx.commands.execute` 就是 Web/TUI 执行斜杠指令的同一条路径，bridge 只需把它接到 RPC 上。

## 1. 新增 RPC 方法（4 个）

| 方法 | 参数 | 返回 |
|---|---|---|
| `command.list` | `{ sessionId }` | `{ commands: [{ name, description, inputHint?, attachments? }] }` |
| `command.run` | `{ sessionId, line, timeoutMs? }` | `{ commandId, kind: 'success' \| 'error', text?, sourceEventSeq? }` |
| `skill.list` | `{ sessionId? }` | `{ skills: [{ name, description, whenToUse?, source, provider, path? }] }` |
| `session.exportZip` | `{ sessionId, destPath? }` | `{ path, fileName, bytes, entries }` |

### command.list
- 活会话校验：`sessions.get` + `agents.get`（复用 `preset.current` 同款解析）；非活会话 → `-32004`。
- 返回 `ctx.commands.list(agent)` 的裁剪映射：`inputHint = descriptor.input?.hint`、`attachments = descriptor.input?.attachments === true`。`definitionId` 属上游不稳定面，**不外泄**。

### command.run
- `line` 必须以 `/` 开头，否则 `-32602`；`execute()` 返回 `undefined`（语法/名称未解析）→ `-32602`，`data.code: 'command/unknown'`。
- `submittedAttachments` 恒传 `[]`（ACP 侧无暂存回执通道）；指令声明需要附件时，上游错误文本原样透传。
- 超时：`timeoutMs` 默认 `180000`（compact 需一次 LLM 摘要）；`AbortController` 到点 abort → `-32000`，`data.code: 'command/timeout'`；bridge 连接断开（`onClose`）时同步 abort 全部在途命令。
- 结果形状**始终**为上游 `CommandExecution.result`（`kind/text/sourceEventSeq`）：处理器级失败（如 compact 的 `busy`）以 `kind:'error' + text` 呈现；RPC 错误只用于信封级问题（未知会话/服务缺失）。
- 忙会话不预检：指令本就设计为随时可调（compact 自报 `busy`、plan 返回 `queued`）。

### skill.list
- `sessionId` 可选：传了用该会话 header 的 cwd 作 lookup（项目级技能按 cwd 生效）；不传用进程 cwd。
- 只输出稳定字段 `name, description, whenToUse?, source, provider, path?`；`invocation/locator/resourceBase` 不外泄。
- 无技能返回空数组（不是错误）。

### session.exportZip
- **懒加载**：首次调用时动态 `import()` 归档模块；解析失败 → 能力位 `false` + 调用时 `-32002`。该包**不进 peerDependencies**（探测失败即降级，不影响插件装载）。
- 流程：`sessionLogExportDeps(ctx)` → `sessionQuery`/`sessionPersistence` 任一缺失即降级 → 活会话先 `flushLiveSessionLog` → `streamSessionLogZip` → 写入 `destPath ?? <os.tmpdir()>/dsh-session-export/<fileName>`（`fileName = sessionLogZipFilename(sessionId)`，目录先 mkdir -p）→ 返回 `{ path, fileName, bytes, entries }`。
- ZIP 不经 ndjson 通道（不 base64），只回路径与字节数；大日志安全。存储态会话同样允许（flush 仅对活会话执行）。

## 2. 服务注入与类型

- 硬 `inject` 不变；新增两个懒解析（沿用 `getAgentPresets` 模式）：
  ```ts
  readonly getCommands: () => CommandRuntime | undefined   // ctx.get('commands')
  readonly getSkills: () => SkillsRegistry | undefined     // ctx.get('skills')
  ```
- `index.ts` 增补 side-effect 类型导入：`@deepseek-ai/dsh-commands`、`@deepseek-ai/dsh-skill`（declaration-merge `Context.commands/skills` 键）。
- `devDependencies` 增补（类型用）：`@deepseek-ai/dsh-commands`、`@deepseek-ai/dsh-skill`、`@deepseek-ai/dsh-session-log-export`（均 `^0.1.5-rc.2`）。

## 3. 能力上报（BridgeCapabilities 增三键）

```ts
commands: boolean       // command.list / command.run
skills: boolean         // skill.list
sessionExport: boolean  // session.exportZip
```

- `commands`/`skills`：握手时 `ctx.get` 探活；
- `sessionExport`：握手时做轻量判断（`ctx.get('sessionQuery')` 存在），首次调用时做模块探测并缓存；
- `BRIDGE_PROTOCOL_VERSION` **保持 1**——纯增量能力位：旧扩展忽略新键，新扩展对旧 bridge 读到 `undefined` 即降级。

## 4. 事件推送

- `DEFAULT_PUSH_TYPES` 追加 `'command/'`：`command/run`、`command/done` 生命周期事件随 `bridge.event` 推送；
- 计划模式切换仍走既有 `plan/mode`（`plan/` 前缀），扩展 banner 自动刷新。

## 5. 配置

| 配置 | 默认 | 含义 |
|---|---|---|
| `commandTimeoutMs` | `180000` | `command.run` 执行超时；到点 abort 并返回 `command/timeout` |

## 6. 实现落点（文件级清单）

- `src/protocol.ts`：`BridgeCapabilities` 三键；`DEFAULT_PUSH_TYPES` 加 `'command/'`；无新错误码（复用 `-32002`/`-32004`/`-32602`/`-32000`）。
- `src/core.ts`：`BridgeCoreDeps` 加 `getCommands/getSkills` 与 export 懒加载句柄；新增 `handleCommandList/handleCommandRun/handleSkillList/handleSessionExportZip` 并注册进 dispatch；连接 `onClose` 联动 abort 在途命令；握手 capabilities 填三键。
- `src/index.ts`：`ctx.get('commands')`/`ctx.get('skills')` 注入；插件头注释能力清单更新。
- `package.json`：`version: 0.1.3`；三个 devDependencies。
- `tests/core.test.ts`：mock commands（list/run/未知指令/超时/断连 abort）、mock skills（list/空/缺失降级）、exportZip（fixture 或 mock archive；包缺失降级）；能力位三态上报。
- `tests/compose.test.ts`：真实 Cordis 组合挂 mock commands 插件，验证 `command.list`/`command.run` roundtrip。
- `README.md` / `README.en.md`：方法表 +4 行、能力说明、配置表 +1 行；「已知限制」追加：export 不经 connection 指令而由 `session.exportZip` 产出文件；`command.run` 仅活会话且不带附件；`skill.list` 为只读目录（调用由模型侧 skill 工具完成）。

## 7. 扩展侧（dsh-lite-vscode）配套方案（已在扩展仓库先行实施，联调点在此）

1. 斜杠菜单分两组渲染，对齐 Web 版式：
   - **指令**：扩展自有指令（file/image/model/effort/permission/new）+ `command.list` 原生指令（按 `capabilities.commands` 门控；选中后 `command.run { line: '/<name> [已输入参数]' }`，结果文本以 system 消息显示）；
   - **技能**：`skill.list` 下发（按 `capabilities.skills` 门控；选中后发送提示词模板 `请使用 ${name} 技能`——模型侧 skill 工具与目录已在 dsh 内注入，会正确调用）；
2. `/export`：菜单固定项，`capabilities.sessionExport` 开时映射 `session.exportZip`，成功后经 `paths.fromDsh` 映射回宿主路径并弹「在文件夹中显示/复制路径」；关闭时隐藏；
3. 手敲 `/compact`、`/plan off` 等原生指令行时，Enter 拦截转 `command.run`（不进入模型 prompt）；`command/`、`plan/mode` 事件按现有订阅推送自然到达。
